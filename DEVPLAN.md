# SaveMoney — план разработки

Трекер расходов для рынка РФ: клон 1Money с фичами, которые просят в отзывах, но которых нет у конкурентов.
План основан на анализе ~1470 отзывов (Google Play 1Money + App Store: Monefy, Деньги ОК, CoinKeeper, Money Flow, Money Note).

## 1. Позиционирование и скоуп по версиям

| Версия | Содержимое |
|---|---|
| **MVP (v1.0)** | Быстрый ввод + виджет · Счета (несколько карт) + подкатегории · Долги (мне должны / я должен) · Отчёты с произвольным периодом · CSV-экспорт (бесплатно всегда) · «До зарплаты» + сменный цикл |
| **v1.1** | Парсер банковских уведомлений (Android, NotificationListenerService) — платная фича |
| **v2.0** | Синхронизация между устройствами + семейный доступ, подписка (Play Billing), iOS-версия |

Принцип: **ввод и данные бесплатны навсегда**. Ничего не блокируем при отписке, CSV всегда бесплатен.
Честная монетизация — прямой ответ на главную волну негатива конкурентов («купил навсегда → отняли → подписка»).

## 2. Зафиксированные решения

- **Стек**: .NET 10 MAUI, C# 13, SQLite (sqlite-net-pcl 1.11.x), CommunityToolkit.Mvvm, CommunityToolkit.Maui.
- **Платформы**: Android-first (целевой релиз), Windows — быстрая отладка без эмулятора. iOS — после MVP.
- **Деньги**: `long` в копейках (minor units). Никаких float/decimal в хранении.
- **Sync-ready с первого дня**: GUID-ключи, `UpdatedAt` (UTC), мягкое удаление `IsDeleted` — v2.0 не потребует миграции данных.
- **Kind-поля** — строковые константы (`Kinds.cs`), не enum: переименование enum'а не ломает БД.
- **UI**: русский-first. resx-локализация — перед стор-релизом (Фаза 3), сейчас строки в XAML.
- **Скорость старта < 1 с** — требование с Фазы 1 (жалоба №1 на Monefy), мерить на бюджетном Android.

## 3. Структура решения

```
save_money/
├── SaveMoney.sln
├── DEVPLAN.md                  ← этот файл
└── src/
    ├── SaveMoney/              # MAUI-приложение (Views XAML, ViewModels, Platforms/)
    ├── SaveMoney.Core/         # ВСЯ логика без UI — тестируется на ПК без эмулятора
    │   ├── Models/             #    сущности + Kinds.cs (константы)
    │   ├── Database/           #    AppDatabase, DbMigrator (PRAGMA user_version), DefaultCategories (сид)
    │   ├── Repositories/       #    Repository<T> (Save/Get/SoftDelete), Account/Category/Transaction/Debt/MerchantRule/Setting
    │   └── Services/           #    BalanceService, MoneyFormat; далее: PaydayService, CsvExport, BankNotificationParser
    └── SaveMoney.Tests/        # xUnit: миграции, сид, CRUD, баланс, долги, мерчант-правила
```

Правило: вся логика, которая может понадобиться без UI (парсер, расчёты, экспорт, синк) — только в Core. В App — только Views/ViewModels/платформенный код.

## 4. Схема БД (SQLite, миграции через `PRAGMA user_version`)

Все сущности наследуют `BaseEntity`: `id` (GUID-строка), `created_at`, `updated_at`, `is_deleted`.

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `accounts` | Счета/карты | name, kind (cash/bank/card), initial_balance_minor, include_in_total, archived |
| `categories` | Категории, 1 уровень вложенности | parent_id (NULL = корень), kind (expense/income), **is_default** (сидные не удаляются) |
| `transactions` | Все операции | account_id, category_id, amount_minor (всегда > 0), kind (expense/income/transfer), transfer_account_id, transfer_amount_minor (курс/комиссия), date_unix, payee, source, raw_text + bank_code + is_pending_review (v1.1) |
| `debts` | Долги | direction (owed_to_me / i_owe), person_name, amount_minor, due_date_unix, account_id, status |
| `debt_payments` | Частичные погашения | debt_id, amount_minor, date_unix |
| `budgets` | Лимиты | category_id (NULL = общий), period_start_anchor_unix + **period_days** (30 = месяц, 14 = смена — это и есть сменный график) |
| `recurring_payments` | Регулярные платежи | шаблон транзакции + recurrence_type (monthly/weekly/every_n_days) + next_date_unix |
| `merchant_rules` | «Магазин → категория» | pattern (подстрока payee), category_id, account_id, use_count (вес) |
| `notification_log` | Дедуп уведомлений (v1.1) | hash (SHA-256), app_package, bank_code, transaction_id |
| `settings` | key-value | payday_day, cycle_anchor_unix + cycle_days, theme, is_pro |

Сид: ~65 RU-категорий с подкатегориями (`DefaultCategories.SeedIfNeeded`, идемпотентно).

## 5. Роадмап

Оценка — «вечера», ~2–4 вечера в неделю. Итог до релиза MVP ≈ 13–14 недель.

### Фаза 0 — каркас ✅ (закрыта 12.09.2026)
Решение, Core-библиотека, БД с миграциями, сид категорий, 15 юнит-тестов, оболочка приложения с табами, DI, smoke-тест Windows.

### Фаза 1 — ядро ручного ввода ✅ (закрыта 12.09.2026)
- ✅ Экран быстрого ввода: кастомная цифровая клавиатура, режимы Расход/Доход/Перевод, чипы счетов и категорий (корень → подкатегории), дата, магазин, заметка.
- ✅ Угадывание категории по магазину + обучение правил при каждом сохранении (`TransactionService`), последняя категория запоминается как кандидат по умолчанию.
- ✅ CRUD транзакций: редактирование через route `transaction?id=` (тот же экран), свайп-удаление мягким удалением.
- ✅ История: группировка по локальным дням с суммами, фильтры (неделя/месяц/3 месяца/всё + счёт), тап → редактирование.
- ✅ Счета: список с балансами, создание/редактирование (тип, начальный остаток, цвет, «учитывать в общем балансе», архивация), удаление.
- ✅ Категории: просмотр деревом (расходы/доходы), добавление категории/подкатегории с выбором иконки, каскадное мягкое удаление не-сидных (`CategoryService`).
- ✅ Тесты: 27/27 — сервисы транзакций (валидация, обучение правил, перевод), история (группировка, фильтры, обе стороны перевода), категории (сортировка, каскад, запрет удаления сидных).
- ✅ Android-сборка компилируется.
- Остаток на полировку (Фаза 3/4): порядок категорий drag-and-drop, автозапоминание счёта по мерчанту, тумблер «быстрая категория» для 2-касаний, замер старта на реальном Android.

### Фаза 2 — долги, регулярные платежи, бюджеты, «до зарплаты» (недели 5–6)
- Модуль долгов: список «мне должны / я должен», частичное погашение, связь со счётом (вернул → доход на счёт), закрытие автоматически при полном погашении (логика `DebtRepository.AddPayment` уже написана и протестирована).
- Регулярные платежи: шаблоны ЖКХ/подписок, напоминание или автосоздание по `next_date_unix`.
- Бюджеты: лимит на категорию и общий; план/факт за текущий период.
- Экран «До зарплаты»: (баланс − предстоящие регулярные до ЗП) / дни до ЗП; дата ЗП из настроек.
- Настраиваемый цикл: период произвольной длины от якорной даты (сменный график).
- **Done**: «хватит ли до 5-го числа» отвечает одним экраном; долг с 2 платежами закрывается сам.

### Фаза 3 — отчёты, экспорт, настройки (недели 7–9)
- Пакет `LiveChartsCore.SkiaSharpView.Maui`: круговая по категориям, динамика по дням/неделям/циклам, доход/расход за период.
- Произвольный период, включая пользовательские циклы.
- CSV-экспорт (бесплатен всегда), PDF — проверить QuestPDF на Android в начале фазы; фолбэк — HTML-отчёт.
- Настройки: тема (светлая/тёмная), день ЗП, цикл, локализация resx (RU → RU+EN), бэкап-копия файла БД.
- Полировка быстрого старта: XAML SourceGen (уже включён), trimming, отложенный DI.
- **Done**: отчёт за произвольный период с графиком и CSV за ≤ 3 действия.

### Фаза 4 — виджет, полировка, релиз MVP (недели 10–12)
- Android-виджет быстрого ввода: нативный `AppWidgetProvider` + RemoteViews, тап → deep-link на экран ввода.
- Полировка UX, пустые состояния, иконка приложения, скриншоты стора.
- Закрытое тестирование Google Play: **12 тестеров × 14 дней** (требование для новых личных аккаунтов) — набрать заранее, в начале Фазы 4.
- Правки по отзывам тестеров → релиз MVP в Google Play.
- **Done**: приложение в открытом/закрытом тесте, виджет добавляет расход без открытия списка.

### v1.1 — парсер банковских уведомлений (сразу после релиза MVP)
- `NotificationListenerService` (Platforms/Android): перехват пушей банковских приложений и СМС-уведомлений. **READ_SMS не запрашиваем** (политика Google Play).
- `BankNotificationParser` в Core: чистые функции, регэкспы по форматам Сбер / Т-Банк / ВТБ / Альфа / Райффайзен; корпус реальных текстов в юнит-тестах.
- Распознанное → транзакция-черновик (`is_pending_review=1`) + локальное уведомление «проверь»; автокатегория по `merchant_rules`.
- Дедуп по SHA-256 текста (`notification_log`).
- **Done**: уведомление «Покупка 500₽ MAGNIT» превращается в транзакцию без ручного ввода; дублей нет; парсер покрыт тестами ≥ 90%.

### v2.0 — синк, семья, подписка, iOS
- Аккаунты + бэкенд (ASP.NET Core minimal API, своя БД) — отдельно спланировать.
- Синк: last-write-wins по `updated_at` + томбстоуны (`is_deleted`); схема уже готова.
- Семейный доступ: общий бюджет, роли.
- Подписка через Play Billing (~99 ₽/мес: парсер, синк, отчёты); `BillingService`-заглушка уже предусмотрена настройкой `is_pro`.
- iOS: ручной ввод + виджеты. iOS-виджеты — только нативный Swift WidgetKit-модуль (C# не умеет), спланировать отдельно.

## 7. Риски и меры

| Риск | Мера |
|---|---|
| iOS-виджеты невозможно написать на C# (WidgetKit) | iOS после MVP; виджет как Swift-модуль или только deep-link |
| QuestPDF не заведётся на Android | Проверка в начале Фазы 3; фолбэк — HTML/только CSV |
| Google Play: закрытый тест 12×14 для новых аккаунтов | Начать набор тестеров в начале Фазы 4 |
| Политика SMS-разрешений | Парсер только через NotificationListenerService, READ_SMS не запрашиваем |
| Старт > 1 с убивает ценность (кейс Monefy) | Контроль с Фазы 1 на реальном устройстве, не в конце |
| Синк v2.0 — главный источник боли | Sync-ready схема (GUID/UpdatedAt/soft delete) заложена с Фазы 0 |
| Зависимости MAUI (поломки при обновлениях) | Версии пакетов закреплены явно в csproj |
